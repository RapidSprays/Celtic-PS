# Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-10-12 | Target one **pinned client build** (24928510) in a copy, not the Steam install. | The live client updates often (6.15.0 today, 7.0.0 in beta). The Steam install must stay unmodified. |
| 2026-10-12 | Stage E (real client on the private server) is the project goal. The owner states the project is authorized. | Owner's direction. |
| 2026-10-12 | The private client strips anti-cheat, Firebase, telemetry, purchases and ads, and **has every live endpoint removed**. The game's own wire protocol is kept. | The owner wants a simpler private setup. Removing live endpoints means a client without anti-cheat can never reach production. Keeping the protocol is less work than rewriting the client's networking. |
| 2026-10-12 | Steam API and ownership checks stay intact. | No DRM bypass. Steam runs alongside. |
| 2026-10-12 | Server in C# / .NET 8, persistence in SQLite. | Same language and protobuf library as the client. .NET 8 SDK is already installed. |
| 2026-10-12 | No Wireshark and no contact with the live game server. | Server responses are rebuilt from the client's own parse code. |
| 2026-10-12 | The server listens on localhost only by default. | Any wider exposure is a separate decision. |
| 2026-10-12 | The private client runs in env **Test** (0) | Uses the world `ip` directly (no DNS), turns on client debug logging, and reports client exceptions to our server. |
| 2026-10-12 | The private client gets its own bundle id (P1) | The live PlayerPrefs hold the owner's real credentials; the private client must never read or send them. |
| 2026-10-12 | The server won't verify the client HMAC or password hashes, and won't embed the client's static keys | They add nothing on a private server. This keeps the client's secrets out of our code. |
| 2026-10-12 | Plan change: there's no anti-cheat to strip (no detectors run). The patch set is P1–P7 in `patch-manifest.md` | Stage B evidence. |
| 2026-10-12 | Vendor upstream lidgren-network-gen3 at f99b006 rather than use a NuGet fork | Wire-identical to the client fork in a direct diff, MIT-licensed and auditable. Local changes: DestoreMessage null check (matches the client fork), and always compiled without DEBUG (release, like the client). |
| 2026-10-12 | New characters spawn at zone 2 (Lir's Reach), point 2003 Highshore Village | From the client balance data; the live server's real choice is unknown (approximated). |
| 2026-10-12 | Starter kit per class from real client data: level-1 class gear (items 10000-10016), tutorial starter skills, 5 Minor Health Potions, 2 class skill books, 50 coins | TutorialConstants and item templates. HP, energy, attack, defence, the levelling curve and potion strength are **approximated** (none of it ships in the client). |
| 2026-10-12 | GM commands use a `.` prefix in normal chat, not `/` | The client sends `/` commands encrypted with a hard-coded client key; plain chat keeps client secrets out of the server. |
| 2026-10-12 | The server reads the client's balance JSON at start-up from the local extraction (`scripts/extract-balance.py`), never from the repo | Item/skill/mob/zone templates are needed for stats and validation. The server still runs without it (zero gear stats). |
| 2026-10-12 | Combat model is **approximated**: mob HP/damage/XP/coins from level × star power (`Game/Mob.cs` MobStats), player swing damage from weapon damage + attack + level, 8% miss, 5% crit ×1.5, 20% potion drop, levelling curve 100·L^1.6 | Real values are server-side data that isn't shipped. Real client data used where it exists: weapon speed and range, mob attack speed and range, skill damage, energy cost, cast time and cooldown. |
| 2026-10-12 | Lir's Reach is auto-populated with 17 camps around its 7 leystones (`Game/ZonePopulation.cs`); named NPCs are placed by GM commands | Owner's choice ("both"). Mob choice follows the zone's quest chain; positions are approximated. |
| 2026-10-12 | Status effects use the client's own strength formula (StatusEffectLevel.GetModifiedAmount) and Hide's level rule (CPlayableCharacter.IsHiddenFrom); flat vs percent application of each EffectType is **approximated** | Tooltips match what the server applies; the server-side effect rules aren't shipped. |
| 2026-10-12 | Levelling: 3 attribute points and 1 skill point per level; points available = earned − spent (so `.level` changes stay consistent); skill rank caps follow the client (CSkillTemplateManager.GetMaxLevel). Vitality +6 HP, Focus +4 energy and +½ skill damage, Strength (melee) / Dexterity (ranged) +1 attack, Dexterity +½ defence | Per-level point counts and attribute effects are **approximated**; rank caps and message flows are from the client. |
| 2026-10-12 | Chests: the 315 container items (by skill link) are catalogued from the client data; contents are **reconstructed** from each item's description (fixed counts, lists, "one random X", named prizes, themed pools) because the server-side LootSets aren't shipped. Mystery Chests use the client's chest-opening screen (InGamePopup 40/41/42). Platinum is now a stored currency. 1.5% chest drop per kill | Owner asked for as many legacy chests as the files contain. |
| 2026-10-12 | Mounts: riding = Mount slot (22) filled and no Dismounted effect (20007), as the client decides; the server sends AppearanceOnlyUpdate after every gear change (the client won't redraw while a mount/saddle is equipped). Mount run speed +40% is **approximated** (mount→speed-effect link is server-only) | Client MountsManager.CheckForMount. |
| 2026-10-12 | Every other combat zone is auto-populated from quest data (`scripts/gen-zone-population.py` → `extracted/<build>/zone-population.json`, outside git). The monster list per zone comes from kill objectives, mob-set kills and monster names in quest text, with seasonal quests skipped and at most 40 types + 12 bosses per zone. Camps sit 18-45 m from leystones, zone exits and quest "travel to" points, and stay out of a 15 m (25 m for bosses) ring around leystones and exits. Levels use per-zone bands in progression order (Crookback 8-14 … Valley of the Ancients 180-220). Farcrag Castle and the Tavern stay peaceful | The client ships no spawn tables or mob levels, so positions, levels and counts are **approximated**. Only x/z matter: the client drops each model from y=100 onto the ground (CMD5_Model.setPosition). |
| 2026-10-12 | Zone travel: exits are the client's own zone-point tables, and arrival is 3 m outside the destination's return portal, towards its nearest leystone (**approximated**: the live arrival points are server-only). Lir's Reach's two Farcrag Castle doors pair with the castle's doors in table order (#4↔#9930, #26↔#9931, a guess). Leystones are discovered within 12 m (**approximated**) and persisted. Fast travel is free: the item limit is set to 10,000 so no Leystone Fragment is needed. Quests aren't implemented, so the 13 quests that gate exits are reported as completed and every exit can be walked through | The owner wants all areas reachable. |
| 2026-10-12 | Multiplayer: players in a zone see each other (ZoningIn/Out, 5 Hz full position snapshots, appearance updates, swing animations, damage with per-recipient health), plus emotes, whispers, party/zone/world chat and parties of up to 6. Kill XP is shared in full with party members within 60 m (**approximated**; loot and coins stay with the killer). The same character logging in twice drops the older session | Owner wants to play with friends. Wire details in `docs/multiplayer-notes.md`. |
| 2026-10-12 | Accounts now have passwords: the first login claims a username, and later logins must send the same client-side password hash. The server stores only a salted PBKDF2-SHA256 verifier of it (this replaces the earlier rule of "no credential columns"). 5 wrong tries drop the connection. GM commands are for the host (connections from the server's own machine) and accounts granted with `.gm` / `--gm`; everyone else gets `.help/.who/.where/.zones` | Needed before friends can connect: otherwise anyone could log in as anyone. Steam ids and device ids are still never stored. |
| 2026-10-12 | Friends connect over **Tailscale** (owner's choice), not port forwarding | The game protocol is plaintext UDP; Tailscale encrypts it and keeps the server off the public internet. |
| 2026-10-12 | Friends get a **kit**, not the game: a self-contained setup tool (`CH.Patcher setup`) that copies and patches the friend's own Steam install, refusing any build other than the verified one (pinned hashes in `KnownBuilds.cs`). The server's `--tailscale` mode binds all interfaces but approves only this machine and Tailscale addresses (100.64.0.0/10, fd7a:115c:a1e0::/48), on both UDP and HTTP | Patched game files are never redistributed. Copies made locally also avoid Gatekeeper problems with a transferred ad-hoc-signed app. Windows waits on the Windows depot's files (`docs/friends.md`). |
